# Проверка профилей — 24 октября 2026

## Условия

Проект Cosplay 2, текущие незакоммиченные изменения поверх HEAD
(идентификатор и контрольные суммы — в [manifest.json](evidence/manifest.json)).
Начальное рабочее дерево было чистым. Три профиля сначала созданы и установлены,
затем испытаны отдельными агентами. Каждый получил исходную задачу и путь
к инструкции, без продиктованного патча. Субагенты наследовали историю текущей
сессии, включая просмотр исходников и настройку профилей: это не слепой
изолированный benchmark. Агенты использовали модель и reasoning текущей сессии по
наследованию; отдельное сравнение моделей не проводилось.

Это проверка поведения навыков в агентном режиме, а не три запуска `codex exec`.
Нативная установка CLI проверена отдельно: `debug prompt-input` подтвердил
загрузку тех же инструкций в developer-сообщение для каждого `-p`.
Полный машинный rollout независимых агентов не экспортировался; сохранены
их задачи, ответы и фактические полные логи Gradle. Скриншоты не требуются:
в качестве доказательств используются логи и отчёты.

## Bug Fix

[Исходная задача](evidence/bug-fix/task.md),
[ответ агента](evidence/bug-fix/response.md),
[сохранённый патч](evidence/bug-fix/fix.patch).

Это воспроизводимый дефект существующей функции, обнаруженный по коду;
пользовательский инцидент на устройстве и runtime-логи не предоставлялись.
`compareAppVersions` удалял нечисловые части после разбиения по дефису:
1.0.0-rc.1 превращалась в четыре числовые компоненты 1,0,0,1.
Функция используется баннером обновления и Android launcher.

Исправление разделяет основную версию, prerelease и build metadata. Стабильная
версия выше prerelease той же основной версии, метаданные не влияют на порядок;
сохранены числовое сравнение, префикс v, нулевые недостающие компоненты и `_`.
В существующий desktopTest добавлены пять методов без новых зависимостей.
Обновлён только затронутый раздел сценария обновлений.

| Проверка | Фактический результат | Доказательство |
| --- | --- | --- |
| Новый регрессионный класс на исходном коде | exit 1, 5 тестов, 4 падения | [red-before.log](evidence/bug-fix/red-before.log) |
| Тот же класс после фикса | exit 0, 5 тестов, 0 падений | [green-after.log](evidence/bug-fix/green-after.log), [XML](evidence/bug-fix/green-tests.xml) |

Точные команды находятся в заголовках логов. Использован существующий Maven mirror
init script из `docs/build-upgrade/`; launcher — установленный JBR 25,
критерий Gradle daemon/toolchain — Java 21. Версии сборки не менялись.
Lint завершился успешно с существующими предупреждениями; это не Kotlin formatting.
Ручная установка APK и работа с живым GitHub Release не проверялись.

## Что дорабатывали

После первых поведенческих попыток инструкции профилей менять не потребовалось;
повторных запусков с улучшенным промптом не было. Первые инструкции остаются
теми же, что установлены в личный Codex; их SHA-256 сохранены в manifest.

При подготовке проверки установки исправлены именно проверочные процедуры:

- CLI отверг --strict-config/--profile для команды features; использован
  поддерживаемый `codex -p <имя> debug prompt-input`.
- В bundled Python отсутствовал PyYAML для штатного quick_validate.py.
  PyYAML 6.0.3 установлен только в игнорируемый `build/profile-validation-deps`;
  зависимости приложения не менялись.
- Первое строгое сравнение текста промпта ошибочно учитывало добавленный runtime
  перевод строки; сравнение исправлено с нормализацией CRLF/LF и краевых переводов.

Эти ошибки и успешные повторные статические проверки сохранены в
[setup-verification.log](evidence/setup-verification.log). Они не переименованы
в успешные первые поведенческие испытания. Валидированы SKILL frontmatter,
YAML интерфейса и TOML профилей; установленные навыки совпадают с исходниками
побайтно. Установщик дважды проверен в отдельной игнорируемой папке: результат
идемпотентен, основной config.toml и посторонний файл сохранены.

## Build Upgrade

По дополнительному запросу основным третьим профилем выбран Build Upgrade;
Review сохранён как дополнительный. В инструкции обновления включены исходная
рабочая база, официальные матрицы совместимости, небольшие связанные шаги,
контроль результата и отмена только собственных правок при регрессии.

Новый профиль проверен отдельным агентом `/root/build_upgrade_trial` без
наследования истории родительской сессии. Задача — аудит готовности текущей
сборки после обновления Android Studio, с запретом обновления компонентов.
[Задание](evidence/build-upgrade/task.md),
[ответ и ссылки на официальные источники](evidence/build-upgrade/response.md),
[логи диагностики](evidence/build-upgrade/logs/).

При первой попытке исходный Wrapper завершился с exit 9009: Java не была доступна
в оболочке. С установленной JBR в JAVA_HOME только текущего процесса Wrapper
завершился с exit 0: launcher Java 25, критерий daemon Java 21. Конфигурационная
проверка `help javaToolchains --info` прошла, фактический daemon использовал
Java 21. Обе компиляционные задачи также завершились с exit 0, но были
UP-TO-DATE; это не свежая перекомпиляция. Тесты, APK и Lint в этом аудите
не запускались. Версии компонентов, конфигурация сборки и код не менялись.

Профиль отметил AGP 9.4.1 выше верхней границы официальной матрицы KMP 2.4.21
(9.3.1). Это риск поддержки, а не установленная причина падения; самовольного
обновления или понижения не было. Исторические успешные сборки не выданы
за новую проверку. Аудит не является испытанием реальной миграции или отката:
эти режимы без запроса на обновление не запускались.

Инструкцию после этого аудита менять не потребовалось. Установка четырёх
профилей, разбор TOML/YAML, совпадение developer-инструкций и сохранение
настроек проверены отдельно: [build-upgrade-setup.log](evidence/build-upgrade-setup.log).
Первый manifest относится к исходным трём испытаниям; после расширения
установщика актуальные контрольные суммы сохранены отдельно в
[build-upgrade-manifest.json](evidence/build-upgrade-manifest.json).
