# Профили агента

Профили доступны в проекте и устанавливаются в личный Codex.
Основные профили: Bug Fix, Research и Build Upgrade. Review — дополнительный.

## Готовые инструкции

| Профиль | Инструкция (единственный исходник) | Задача и результат |
| --- | --- | --- |
| Bug Fix | [SKILL.md](../../../.agents/skills/profile-bug-fix/SKILL.md) | Воспроизвести баг, найти причину, исправить, проверить регрессии; «Что нашёл / починил / проверил» |
| Research | [SKILL.md](../../../.agents/skills/profile-research/SKILL.md) | Исследовать код без изменений; «Файлы / связи / выводы / ограничения» |
| Build Upgrade | [SKILL.md](../../../.agents/skills/profile-build-upgrade/SKILL.md) | Проверить совместимость, обновлять небольшими шагами, проверить сборку и откатить неудачный шаг |
| Review | [SKILL.md](../../../.agents/skills/profile-review/SKILL.md) | Проверить diff без изменений; findings с приоритетом, триггером и влиянием, покрытие и ограничения |

Каждая инструкция содержит обязанности, запреты и формат ответа. Во всех режимах
действуют AGENTS.md и профильные навыки проекта. Профили не закрепляют модель,
провайдера или уровень reasoning: используются настройки пользователя.

## Включение в Codex

Из корня проекта в PowerShell:

```powershell
.\.codex\install-profiles.ps1
```

Установщик копирует четыре навыка в `$CODEX_HOME/skills` (по умолчанию `~/.codex/skills`)
и создаёт рядом с пользовательским `config.toml` файлы `bug-fix.config.toml`,
`research.config.toml`, `build-upgrade.config.toml`, `review.config.toml`. Из тела SKILL.md генерируются
`developer_instructions`; это инструкция профиля, а не замена базового системного промпта.
Основной `config.toml`, существующие роли `.codex/agents` и остальные навыки не меняются.
Повторная установка обновляет только эти четыре именованных профиля и навыка.
Для проверки в отдельной папке есть параметр `-Destination <папка>`.

В новом чате приложения можно выбрать навык через `$` или написать:

```text
$profile-bug-fix Исправь баг: <симптом, ожидаемое поведение>.
$profile-research Какие внешние эндпоинты используются и чем покрыты тестами?
$profile-build-upgrade После обновления Android Studio перестала собираться сборка. Найди причину и восстанови совместимую конфигурацию с проверками.
$profile-review Проверь текущие незакоммиченные изменения.
```

Репозиторные навыки доступны при открытом проекте; личные копии — в других проектах.
После установки начните новый чат, чтобы обновился список доступных навыков.
Выбор навыка задаёт поведение, но сам по себе не переключает разрешения приложения.
Research/Review запрещают изменения инструкцией; используйте read-only разрешения
приложения, если нужна принудительная защита.

Нативные профили CLI запускаются отдельно:

```powershell
codex -p bug-fix "Исправь баг: <описание>"
codex -p research "Какие внешние эндпоинты используются и чем покрыты тестами?"
codex -p build-upgrade "Обнови зависимости до совместимого стабильного набора; сохрани поведение и проверь обе платформы"
codex -p review "Проверь текущий diff"
```

У Research/Review в CLI дополнительно задан `sandbox_mode = "read-only"`.
Bug Fix и Build Upgrade наследуют разрешения пользователя. Установщик не ослабляет настройки
безопасности и не включает профиль по умолчанию.

Формат отдельных `*.config.toml` подтверждён установленным `codex-cli 0.163.0-alpha.11.1`
и [официальной документацией](https://learn.chatgpt.com/docs/config-file/config-advanced).
В текущем Codex `--profile` выбирает отдельный файл; старые таблицы `[profiles.*]`
для этого не используются. Поле `developer_instructions` описано в
[справочнике конфигурации](https://learn.chatgpt.com/docs/config-file/config-reference).

## Испытания

Задачи, ответы независимых агентов, логи проверок и оценка первой попытки находятся
в [REPORT.md](REPORT.md). Логи используются вместо скриншотов. Наличие файла
профиля и успешный разбор конфигурации отдельно от успешного выполнения задачи.

## Обновление сборки без потери рабочего состояния

Build Upgrade сначала проверяет исходную сборку и официальную совместимость
Android Studio, AGP, Gradle, Kotlin/Compose и JDK. JBR самой IDE, JVM Gradle,
toolchain, bytecode target и JDK CI рассматриваются отдельно. Обновление IDE
само по себе не требует повышения всех версий проекта.

Изменения выполняются небольшими связанными шагами с проверками и сохранением
исходного содержимого затронутых файлов. При регрессии профиль исправляет шаг
либо отменяет только свои правки; чужие изменения сохраняются. Не использует
сброс репозитория, отключение тестов или удаление глобальных кэшей.
Итоговая проверка обновления включает обе компиляции, тесты, Android Lint и debug APK.

Гарантии отсутствия любых поломок нет: ручная синхронизация IDE и запуск
на устройстве проверяются отдельно и указываются в отчёте. Если запрос касается
только аудита, профиль даёт диагноз и план, не обновляя компоненты.
