Реализуй небольшой сервис FestivalSearch в существующем feature/festival commonMain,
в пакете ru.flobsterable.cosplay2.feature.festival. Публичный метод search принимает
List<FestivalSummary> и строку запроса, возвращает совпадения без изменения входного
списка и с сохранением его порядка. Поиск регистронезависимый по title и city;
запрос разбивается по любым пробельным символам, все слова должны встретиться
хотя бы в одном из этих двух полей (слова могут совпасть в разных полях).
Пустой/пробельный запрос возвращает все элементы, пустой список — пустой результат.
Сеть, storage, UI-интеграция и новые зависимости не нужны.

Добавь содержательные unit-тесты в существующий composeApp desktopTest, включая
кириллицу, несколько слов, смешанные поля, пробелы, отсутствие совпадений,
пустые данные и сохранение порядка/входного списка. Кратко опиши сервис в docs.
Прочитай применимые AGENTS.md и используй $kmp-architecture, $kotlin-code-style,
$compose-multiplatform (оцени, нужна ли UI-интеграция) и $kmp-testing.
Запусти настроенных code-reviewer и test-engineer как настоящих субагентов:
первый независимо проверяет diff без исправлений, второй выполняет обе компиляции,
desktopTest для composeApp/core:platform, Android lintDebug и git diff --check.
Сохрани выводы ролей и результаты команд в docs/ai-agent/v1/ с полными логами и
exit codes. Если Java не найдена, используй установленный Android Studio JBR через
JAVA_HOME текущего процесса. Не изменяй toolchain, правила, skills или конфигурации
агентов. Выполни задачу за один запрос без уточнений. Не исправляй реализацию после
получения первого результата проверки; зафиксируй дефекты отдельно для сравнения v2.
