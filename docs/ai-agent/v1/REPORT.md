# Конфигурация AI-агента и первая генерация v1

Дата: 23 октября 2026. Репозиторий: Cosplay 2. Codex CLI: 0.163.0-alpha.11.1.

## Установленная конфигурация

Глобальные личные правила установлены в ~/.codex/AGENTS.md; их версионируемая
копия находится в docs/ai-agent/global/AGENTS.md. Корневой AGENTS.md описывает
реальную архитектуру, стек, naming, пять примеров кода, пять антипаттернов,
Kotlin-шаблон, Coroutines/Flow/state и проверки.
Локальные правила добавлены для composeApp, core/platform, data/festival,
feature/festival. Для остальных модулей достаточно корневых правил.

Четыре repo skills: kmp-architecture, kotlin-code-style, compose-multiplatform,
kmp-testing. Все прошли официальный quick_validate.py из skill-creator:
см. skill-validation.json. Для валидатора PyYAML установлен только в рабочий
временный каталог, зависимости проекта не менялись.

Две роли объявлены в поддерживаемом формате .codex/agents/*.toml с name,
description и developer_instructions. Они наследуют разрешения родителя;
инструкция reviewer не редактировать файлы не является отдельной sandbox.

## Проверка загрузки и запуска

verify-discovery.ps1 вызывает реальный codex debug prompt-input. Получены
40 успешных assertions в пяти контекстах: корень и четыре локальных модуля.
Проверена видимость глобальных/проектных/локальных правил, четырёх skill names
и двух ролей: discovery-checks.json и discovery-prompt.json.

Обе custom roles действительно вызваны через spawn_agent с agent_type
code-reviewer и test-engineer: точные вызовы извлечены из rollout в
subagent-spawns.json. Это проверка runtime, а не только TOML/YAML синтаксиса.

## Первая генерация

Неизменный исходный запрос — prompt.md. База — base-commit.txt.
Модель запуска — gpt-6-sol. До генерации был неуспешный запуск с пользовательской
моделью gpt-5.4: сервер отклонил её. Исходники при этом не генерировались;
startup-failed-* сохраняют эту ошибку. Пользовательская конфигурация модели не менялась.

Один запрос создал FestivalSearch, шесть unit-тестов и описание в feature-flows.
Промежуточных уточнений и повторного запроса на реализацию не было.
Архивные код и тесты в source/ после первой проверки не исправлялись.
Рабочие тесты впоследствии исправлены отдельным изменением, описанным ниже.
Снимки исходников — source/, diff новых и изменённых файлов — generation.diff,
SHA-256 — generation-manifest.json. Инструкции на момент запуска сохранены в
configuration-snapshot.zip, root-AGENTS.snapshot.md и instructions-manifest.json.

При аудите исправлена упаковка configuration-snapshot.zip: исходные байты всех
11 файлов из instructions-manifest.json сохранены, локальным AGENTS.md возвращены
пути модулей. Первоначальный ZIP оставлен как configuration-snapshot.original.zip.
Данные восстановления и SHA-256 — artifact-recovery.json.
После нормализации переводов строк Git архивные Kotlin-файлы source/ восстановлены
до исходных SHA-256 из generation-manifest.json, а root-AGENTS.snapshot.md —
до исходных байтов из ZIP; содержательные правки не вносились.
Для архивных исходников и журналов в .gitattributes отключена нормализация строк.

generation-events.jsonl — неполный CLI-экспорт: последняя, 44-я строка оборвана,
а generation-exit-code.txt содержит 1. Причина этого кода не установлена; исходные
файлы не исправлялись и не считаются доказательством успешного экспорта.
Полный журнал сессии восстановлен из локального Codex rollout в
generation-rollout.recovered.jsonl (формат rollout отличается от CLI events).
Он содержит финальный ответ и task_complete, один запрос реализации и реальные
запуски обеих ролей. Автоматически приложенные AGENTS.md и четыре skills не являются
дополнительными запросами пользователя. Новая генерация при восстановлении не запускалась.

## Оценка качества

Сервис соблюдает границу модуля, не добавляет dependencies, сеть, storage или UI.
Ввод разбирается через Char.isWhitespace, сопоставление — contains(ignoreCase=true),
для слов используется AND, для двух полей — OR; порядок и исходный список сохраняются.
Независимый code-reviewer не обнаружил дефектов по статическому анализу, но реальные
тесты выявили три противоречивых ожидания: запрос «Омск» совпадает также с «Томск»
при поиске подстроки. Исходные тесты ошибочно ожидают исключения такого совпадения.
В архиве v1 это не исправлялось. Статическое ревью само по себе не заменяет
исполнение тестов.

## Последующее состояние проекта

При отдельном исправлении toolchain отрицательные примеры «Томск» в рабочих тестах
заменены на «Казань» и добавлен явный тест поиска подстрок. Теперь рабочих тестов
FestivalSearch семь; реализация сервиса и архив source/ не менялись. Основание —
[TOOLCHAIN-FIX.md](../../build-upgrade/TOOLCHAIN-FIX.md).
После перехода на JDK 21 текущая проверка дала 35 успешных тестов composeApp и
12 core/platform, компиляции Android/Desktop и debug APK успешны; Android Lint —
0 errors, 2 warnings. Подробности актуального аудита — [AUDIT.md](../AUDIT.md).
Это последующее исправление рабочего проекта, а не повторная генерация v2.
Исторический docs/build-upgrade/v1-source-integrity.json относится к этапу до
исправления тестов; текущие сравнения с архивом — ../current-source-integrity.json.

## Ограничения оценки влияния правил

Вероятно полезны реальные пути и зависимости модулей, конкретные образцы кода,
описание test harness и запрет новой UI-интеграции в исходном запросе. Это качественное
наблюдение, а не измеренное влияние отдельных инструкций.
Измерить вклад каждого правила отдельно по одному запуску нельзя; контрольной
генерации без правил не выполнялось. Правила по результатам теста не улучшались.
Актуализация фактов о версиях/Android-командах при отдельной миграции сборки
не является v2 инструкций. Для честного повтора нужно использовать прежнюю базу,
тот же prompt и сопоставимое окружение, отдельно указав изменённый toolchain.
