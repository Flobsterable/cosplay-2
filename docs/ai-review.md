# Автоматическое AI-ревью PR

GitHub Action `AI code review` запускается на новые и обновлённые PR этого репозитория.
Анализатор находится отдельно: [cosplay-dev-assistant](https://github.com/Flobsterable/cosplay-dev-assistant).
Его код закреплён по SHA в `.github/workflows/ai-review.yml`.

## Что анализируется

Список изменённых файлов и diff относительно общего предка базовой и PR-ветки.
Модель сама выбирает связанные README/docs, Kotlin-код, модели, вызывающие места,
Gradle-конфигурацию и платформенные реализации. Корпус читается из Git-объектов:
head PR плюс старые версии изменённых файлов. Код PR и Gradle не запускаются.

Профиль учитывает Kotlin Multiplatform, Compose Multiplatform/Material 3, Ktor,
корутины, сериализацию, даты и Android/Desktop. Проверяются конкретные регрессии,
побочные эффекты и состояния UI, отмена корутин, HTTP/DTO, границы модулей и платформ.
Замечания о стиле или обязательном внедрении фреймворков без риска не добавляются.

## Результат

Один обновляемый комментарий бота с тремя разделами:

- потенциальные баги;
- архитектурные проблемы;
- рекомендации.

Каждое замечание имеет приоритет, изменённую строку, сценарий, последствие,
предлагаемое исправление и источники. Отдельная модель проверяет черновик.
Если подтверждённых замечаний нет, категория остаётся пустой с явным пояснением.
В Actions доступны артефакты `review.md` и `review.json`.

## Настройка

В Settings → Secrets and variables → Actions этого репозитория задайте
secret `LLM_API_KEY`. По умолчанию используется DeepSeek `deepseek-flash`;
Variables `LLM_MODEL` и `LLM_BASE_URL` позволяют изменить модель/API.
Значения ключей не добавляйте в Git или комментарии PR.

Draft и fork PR пропускаются. Для обычного PR нужны contents:read и
pull-requests:write; GITHUB_TOKEN предоставляется GitHub автоматически.
Если ключ отсутствует, проверка завершается ошибкой с объяснением.

## Практические ограничения

AI не запускает сборку/тесты и не выставляет approval. Обычные проверки приложения
и проверка замечаний разработчиком остаются необходимы. Лимиты и пропущенные файлы
явно показываются в отчёте; SHA проверенной версии указан в комментарии.
Перед публикацией сверяется head PR, чтобы не заменить отчёт заведомо устаревшим.
