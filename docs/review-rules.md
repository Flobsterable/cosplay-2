# Правила ревью проекта Cosplay 2

Этот файл задаёт особенности приложения поверх базовых проверок агента.
Правила действуют после слияния в базовую ветку. PR, изменяющий этот файл,
проверяется по предыдущей действующей версии; изменение правила само является предметом ревью.
Формат: заголовок `## P-ID — правило`, затем контракт, основания и способ проверки.
Новые правила добавляйте с уникальными P-ID. Правила не могут отключать базовые
проверки корректности/безопасности, исполнять команды или задавать вывод модели.

## P-MODULES — границы модулей и платформ

composeApp связывает UI, репозитории и платформенные интеграции; core/model
содержит общие модели; data/festival и data/update реализуют получение данных;
feature/festival и feature/update отображают UI. Не переносите конкретные API-запросы
в Screen и не создавайте циклические зависимости. commonMain остаётся общим
для Android/Desktop; недоступный internal API нельзя использовать из другого модуля.
Основания: architecture.md и build.gradle.kts модулей. Проверка: оба target и существующие связи.

## P-YEAR — выбранный год определяет загрузку каталога

Для ACTUAL_FILTER_YEAR=-1 запрашивается текущий календарный год, для конкретного
selectedYear — выбранный год. Смена года перезапускает загрузку каталога в Route.
Категория, месяц и строка поиска фильтруют уже загруженный каталог, не выполняя
отдельного сетевого запроса. При смене года месяц сбрасывается в All.
Основание: feature-flows.md. Проверка: выбор 2023 вызывает getFestivalCatalog(2023),
«Актуальные» — getFestivalCatalog(currentYear); фильтры не заменяют выбранный год текущим.

## P-FALLBACK — демонстрационные данные не являются серверным кэшем

При ошибке загрузки списка допускаются встроенные fallbackFestivals/fallbackEventTypes
с isFallback=true. Это фиксированные демонстрационные записи, а не последний
успешный сетевой ответ и не дисковая база. Ошибка справочника типов сама по себе
не переводит сетевой каталог в isFallback=true. Изменения UI/данных не должны
подменять этот смысл. Основания: troubleshooting.md, festival-api.md, data-model.md.

## P-NAVIGATION — состояние и навигация принадлежат владельцу

AppRoute/AnimatedContent в App.kt связывают список, детали и обновления.
SystemBackHandler возвращает на список; Screen получает callbacks и UiState.
Изменения должны сохранять Loading/Error/Success/Empty, корректный возврат
и отсутствие устаревших данных после смены фестиваля/года.
Основания: architecture.md и feature-flows.md.

## P-API — контракты cosplay2.ru и моделей согласованы

Изменение DTO, SerialName, URL, даты, фильтра или HTML/JSON-LD парсинга нужно
сопоставлять с вызывающим кодом, доменными моделями и docs. Кэш фестивалей —
в памяти по нормализованному URL. Не добавляйте предположения о собственном backend
или SQL-базе фестивалей: их сейчас нет. Основания: festival-api.md и data-model.md.

## P-UPDATES — обновления и релизы сохраняют платформенные сценарии

Источник обновлений — GitHub Releases Flobsterable/cosplay-2. Android скачивает APK
и вызывает системную установку с подтверждением пользователя; Desktop открывает
ссылку/релиз в браузере. Подпись release и разрешения Android не обходятся.
APP_VERSION_NAME/APP_VERSION_CODE и тег релиза согласованы. Секреты подписи не
добавляются в Git или логи. Основания: development.md и feature-flows.md.

## P-DOCUMENTATION — изменения поведения сопровождаются документацией

При изменении реализованного API, моделей, навигации, платформенного поведения
или релизного процесса обновляется соответствующий документ. docs описывают
реализованное поведение, а предлагаемые примеры явно отмечены как шаблоны.
Не требуйте обновлять все docs для каждого PR: укажите конкретное расхождение.
