# Подключение помощника разработчика к Cosplay 2

## Где хранится контекст проекта

Единственный источник документации приложения — README.md и docs/ этого репозитория.
Архитектура, API cosplay2.ru, модели, экраны, сценарии и релизы описываются здесь.
Особенности ревью и продуктовые контракты хранятся в [review-rules.md](review-rules.md).
Общие правила KMP и код помощника находятся в отдельном репозитории
[cosplay-dev-assistant](https://github.com/Flobsterable/cosplay-dev-assistant).
Копии документации Cosplay 2 в агенте не поддерживаются и не используются.

## Консоль на VPS

Копия приложения: /home/user/projects/cosplay-2. Она должна содержать актуальный develop.
В локальном tools/dev-assistant/.env репозитория агента задаются:

```dotenv
PROJECT_PATH=/home/user/projects/cosplay-2
PROJECT_ROOT=/home/user/projects/cosplay-2
```

PROJECT_PATH используется Docker для монтирования, PROJECT_ROOT — при запуске Node.
В Docker путь внутри контейнера автоматически задаётся как /project.
API-ключ DeepSeek хранится только в локальном .env; в Git его не добавляют.

/help читает README.md и docs/**/*.md этой копии приложения; MCP сообщает текущую ветку.
После слияния изменений обновите копию приложения через git pull --ff-only.
/sync BASE получает закоммиченный diff и предлагает обновление существующей документации.
По умолчанию выводится diff; --apply сохраняет изменения. Агент сам не коммитит их.

## Ревью PR

Workflow закрепляет версию общего агента по SHA. Его базовый профиль задаёт общие
проверки KMP, а docs/review-rules.md из базовой ветки этого репозитория — особенности Cosplay 2.
Код и документация для ревью читаются из Git-снимков PR, а не из примеров агента.
Подробности запуска и история отчётов: [ai-review.md](ai-review.md).
