# Автоматическое обновление документации

После изменения кода в develop/main workflow Update project documentation запускает
агента на VPS через runner cosplay-vps с меткой cosplay-agent. Это тот же
cosplay-dev-assistant; исполняется закреплённая проверенная версия его кода.
Приложение и его скрипты не запускаются. Агент сравнивает весь диапазон push
before..after, читает README/docs и исходники и коммитит проверенные изменения
документации прямо в исходную ветку.

## Ключи и доступ

LLM_API_KEY и GEMINI_API_KEY хранятся только на VPS в
~/cosplay-dev-assistant/tools/dev-assistant/.env с правами 600. Workflow читает
значения как данные, без source/exec, маскирует ключи и передаёт только разрешённые
настройки модели. PROJECT_ROOT, PATH и команды из .env не используются.
Ключи моделей в GitHub Secrets и AGENT_DISPATCH_TOKEN для docs-sync не требуются.
Для чтения и docs-коммита используется временный GITHUB_TOKEN текущей задачи
с contents:write; для recovery issue — отдельный job с issues:write.

На текущем VPS Google возвращает User location is not supported for the API use.
Поэтому по решению владельца в серверном .env установлено:

    DOCS_SYNC_USE_PRIMARY_ONLY=true

В этом режиме документация обрабатывается только основной моделью DeepSeek;
ключ Gemini остаётся на сервере. Это явный выбор провайдера до запросов, а не
автоматический fallback после ошибки. Чтобы снова использовать Gemini для
небольших задач, устраните региональную блокировку и установите флаг false.

## Защита от лишних расходов

Экономный конвейер подбирает источники локально и обрабатывает документы порциями.
Расход ограничен LLM_MAX_CALLS и LLM_MAX_INPUT_CHARACTERS в серверном .env.
Подписанный кеш ответов хранится в приватном каталоге
~/.cache/cosplay-dev-assistant/docs-responses. Ошибка модели или конфликт push
не запускает повторную генерацию автоматически. Задачи одной ветки идут
последовательно через queue:max. Диапазон, уже отмеченный Docs-Sync-Source
в истории коммитов, пропускается.

## Результат и восстановление

Исполнение и логи видны в Actions cosplay-2 → Update project documentation.
При обновлении публикуются только README.md и Markdown в docs/; если правки
не нужны, коммита нет. Каждый документ проверяется до сохранения, относительные
ссылки проверяются локально. Семантическая точность также зависит от модели.
Docs-only push не запускает новый цикл генерации.

При ошибке/отмене job отслеживания создаёт или обновляет recovery issue для
точного диапазона branch/head. Старые маркеры долга поддерживаются. Issue содержит
метаданные и ссылку на запуск, без ответов модели. При конфликте push проверенный
patch сохраняется в артефакте docs-sync-generated.patch на 14 дней, без force push.

После устранения причины используйте Run workflow на develop/main с base/head
из issue. Успешное восстановление закрывает только долг этого диапазона.
Runner установлен как systemd-сервис, поэтому отключение SSH его не останавливает.
Если runner offline, проверьте его сервис на VPS. Основные тесты —
node --test .github/scripts/*.test.cjs; платные API в тестах подменяются.
