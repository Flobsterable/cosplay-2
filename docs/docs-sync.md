# Автоматическое обновление документации

Документы develop/main описывают уже слитый код. После изменения Kotlin, Gradle,
TOML или настроек синхронизации workflow **Update project documentation** отправляет
диапазон before..after в **cosplay-dev-assistant**. Агент проверяет README/docs,
дополняет устаревшие описания и создаёт отдельный docs-коммит в исходной ветке.

## Где выполняется агент

Приложение только отправляет задачу. Весь анализ, вызовы моделей, проверки,
кеширование и публикация результатов выполняются в **cosplay-dev-assistant →
Actions → Agent service**. Ключи GEMINI_API_KEY, LLM_API_KEY, настройки моделей
и бюджеты принадлежат репозиторию агента. В cosplay-2 ключи моделей не нужны.

В cosplay-2 настройте один Actions Secret **AGENT_DISPATCH_TOKEN**: fine-grained
GitHub PAT с доступом **Actions write к cosplay-dev-assistant** для запуска
workflow Agent service. Это токен отправки задач, а не ключ LLM.
У агента отдельно задаётся **PROJECT_GITHUB_TOKEN** с Contents, Pull requests и
Issues read/write к cosplay-2, чтобы читать код, оставлять inline-замечания,
публиковать документацию и вести recovery issues. Защита ветки не обходится.

Полная настройка: [сервис агента](https://github.com/Flobsterable/cosplay-dev-assistant/blob/main/docs/agent-service.md).
Сначала workflow сервиса должен попасть в default branch агента; затем подключаются
отправители приложения. Один reusable workflow не переносит секреты репозитория агента.
Токен отправки не получает Contents write и не может менять код агента.

## Проверка результата

Зелёный job в cosplay-2 означает доставку задачи. Результат самой генерации,
ошибки и артефакты находятся в Actions **агента**, в запуске Agent service.
Агент не исполняет scripts, Gradle или npm приложения. Публикуются только README.md
и Markdown в docs/. Каждый документ проверяется до сохранения; смысловая точность
зависит в том числе от модели. Непроверенные правки не коммитятся.

Если документация актуальна, коммит не нужен. Уже обработанный диапазон пропускается
по маркеру Docs-Sync-Source в истории. Push только README/docs не запускает новый
цикл. Ревью PR публикует только комментарии к строкам кода.

## Восстановление после ошибки

При ошибке или отмене центрального docs-sync агент создаёт/обновляет Issue
«Документация не обновлена» в cosplay-2 со ссылкой на свой запуск и точными SHA.
Следующий мердж не закрывает долг прежнего диапазона. В issue нет ответов модели
или логов. Если ошиблась сама отправка, это видно в Actions cosplay-2; центральный
агент ещё не получил задачу и не может создать recovery issue.

Исправьте причину и запустите Actions → **Update project documentation → Run
workflow** в cosplay-2: выберите develop/main, укажите base/head из issue.
Либо используйте Agent service → Run workflow в репозитории агента с type=docs-sync,
repository=Flobsterable/cosplay-2, branch и исходным base/head. Успешное восстановление
закрывает issue только своего диапазона.

Платный конвейер не перезапускается автоматически, в том числе при HTTP 402 или
конфликте push. Проверенные правки при конфликте сохраняются в артефакте агента
**docs-sync-generated.patch** на 14 дней. Force push не применяется.
Для исправленной версии используйте новый Run workflow: Re-run jobs старого запуска
повторяет его старую версию.
