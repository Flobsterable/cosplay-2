# Поддержка пользователей Cosplay 2

## Почему вместо каталога видны демонстрационные фестивали?

При ошибке загрузки приложение может показать встроенные демонстрационные записи
с isFallback=true. Это не кэш последнего успешного ответа сервера. Проверьте соединение,
выбранный год и повторите загрузку позже. Если в тикете есть HTTP 503, сервер был
недоступен в момент запроса; это не доказывает, что он недоступен сейчас.
Платформу, версию и выбранный год уточняйте по данным пользователя/тикета.

## Почему не виден нужный фестиваль?

Проверьте год, категорию, месяц и текст поиска. Год определяет запрос каталога;
остальные фильтры применяются к загруженным данным. Для «Актуальные» запрашивается
каталог текущего календарного года, но показываются только записи со статусом
FestivalStatus.Future, полученным из timestatus сервера. Поэтому событие текущего
года может не попасть в «Актуальные», если у него другой статус. Каталог берётся
с cosplay2.ru; собственного каталога
на отдельном сервере приложения нет. Не обещайте наличие события без подтверждения.

## Почему на компьютере обновление открывается в браузере?

Это штатное поведение Desktop. На Android приложение скачивает APK и вызывает
системную установку с подтверждением пользователя; Desktop открывает ссылку на релиз.
Источник обновлений — GitHub Releases Flobsterable/cosplay-2.

## Почему Android не устанавливает обновление?

Для APK может потребоваться разрешение установки из этого источника в системных
настройках. После выдачи разрешения вернитесь в приложение. Не отключайте защиту
системы и не используйте случайные APK. Если ошибка остаётся, уточните версию,
устройство, текст системной ошибки и версию установленного приложения.

## Есть ли вход в аккаунт и как восстановить пароль?

Документация текущего клиента описывает фестивали и обновления, но не реализованную
авторизацию, аккаунты или восстановление пароля. Не выдумывайте такую возможность.
Уточните, идёт ли речь о cosplay2.ru, GitHub или другом сервисе. Не запрашивайте пароль.

## Что указать для диагностики?

Платформу, версию приложения, выбранный год/фильтры, ожидаемый результат и описание
ошибки. Не отправляйте API-ключи, пароли, токены или личные данные. При отсутствии
данных поддержки нужно задать уточняющий вопрос, а не объявлять предположение фактом.

## Как работает чат поддержки?

Экран чата добавляется отдельно. Сервис поддержки — самостоятельный агент с RAG
по этой документации и MCP-контекстом пользователя/тикета. Внутренний API предназначен
для вызова доверенным бэкендом. Автоматическая передача оператору и изменение
аккаунтов сейчас не реализованы; рекомендация обратиться к человеку не означает,
что обращение уже создано. Подключение Android/Desktop экрана к бэкенду выполняется отдельно.
