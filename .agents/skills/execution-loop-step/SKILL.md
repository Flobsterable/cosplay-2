name: execution-loop-step
description: "Выполнить один запланированный шаг Execution Loop в отдельной сессии и передать проверяемый результат следующему шагу."
---

Примени incremental-implementation и context-engineering в проектной адаптации.
Прочитай план, текущий шаг, выполненные шаги, AGENTS.md и указанные в шаге skills.
В prompt есть краткая сводка, полные критерии/описание и handoffs — в contextFile.
Читай предыдущие детали по необходимости; не загружай весь журнал каждого шага.
Если передан reviewFeedback, исправь подтверждённые findings в текущем финальном
шаге и проверь все критерии заново. Не объявляй собственный ответ независимым ревью.
Выполни только текущий шаг; сохрани работу предыдущих шагов. Не вызывай execution-loop
рекурсивно. Промежуточный DONE означает готовность шага, а не всей задачи.
Для финального шага проверь все критерии исходной задачи
с отдельным наблюдаемым свидетельством для каждого пункта: команда/assert либо
шаг UI smoke и снимок. Сборка сама по себе не подтверждает текст, иконку или callback.
Не выдавай частичную проверку критериев за готовность всей задачи. Не запускай
фоновые задачи, новые очереди и автоматизации; следующим шагом управляет runner.
Выполни two-level-testing
для кода; docs — git diff --check. Верни текущую verificationDirectory относительно
рабочей копии. После восстановления старые свидетельства не переиспользуй:
сформируй новый verification run для актуального полного diff.

В JSON handoff передай summary, files, decisions, risks и verification с точными
command/result. Отделяй выполненные проверки от предложенных/пропущенных;
не скрывай ошибку в кратком summary. Это передаётся следующему шагу и ревьюеру.
Summary — до 600 символов; result каждой проверки — до 300 символов и ссылка
на полный лог при необходимости. Не вставляй в JSON код, полный вывод Gradle,
содержимое файлов и повтор критериев. Ошибки и необходимые свидетельства сохраняй.

Сохраняй первые результаты проверок. firstPass=false после неудачной проверки
решения, даже если последующее исправление помогло. Ожидаемый RED регрессионного
теста до исправления бага учитывается отдельно. При ошибке сохрани контекст,
ожидание/факт и журналы, верни FAIL/BLOCKED обработчику. Сам не повторяй одну
неуспешную команду бесконечно. Коммиты и перенос изменений делает runner.
