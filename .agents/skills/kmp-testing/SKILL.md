# KMP testing

Для отмены и смены параметров смотри [управляемый suspend-тест](references/cancellation.md).
Шаблон использует существующие зависимости; не добавляй его в приложение без задачи.

Прочитай корневой и применимые вложенные AGENTS.md. Выбирай проверки по изменённому
поведению; соблюдай явно заданные границы задачи и замороженные артефакты.
Найди изменённый контракт и существующие тесты: composeApp/src/desktopTest,
core/platform/src/commonTest и desktopTest. Используй kotlin.test и имеющиеся
fakes/Compose harness; новые библиотеки для локального теста не нужны.

Проверь значимые ветви: успех, пустой ввод, ошибка, отмена suspend-операции,
смена ключа/повторный вызов — по применимости. Для Flow проверяй наблюдаемое
состояние и контролируй жизнь collection; не используй Thread.sleep.
Не обращайся к реальной сети в unit tests. Не тестируй только собственные mock-настройки.

Для исправления бага добавляй воспроизводящий причину регрессионный тест, если
задача разрешает изменение тестов; иначе сообщи пробел покрытия. Проверяй контракт
и наблюдаемое поведение, а не имена private helpers или порядок вызовов без
продуктового значения. Правка текста/чистое перемещение не требуют зеркальных тестов.

Для use cases подставляй repository/storage через существующие интерфейсы.
Для конкуренции контролируемо задержи первую операцию: проверь повторное действие,
смену параметра до завершения, устаревший успех/ошибку, отмену и флаги новой операции.
Для storage проверь старый формат, ошибку чтения/записи и сохранение данных/backup
при reset по затронутому контракту; используй временные файлы вместо пользовательских.
Для UI после декомпозиции проверь действия, состояния, возврат и сохранение фильтров;
при изменении ресурсов — их сборку для обеих платформ. Ручная проверка темы,
адаптивности и доступности указывается отдельно от результатов автотестов.

Для изменений кода запускай Wrapper из корня. В Windows используй .\gradlew.bat:

- :composeApp:compileKotlinDesktop и :composeApp:compileAndroidMain;
- :composeApp:desktopTest и :core:platform:desktopTest (или --tests для класса);
- :androidApp:lintDebug для Android Lint, git diff --check для whitespace.

Для правок только инструкций проверь diff, ссылки и формат изменённых файлов;
компиляция приложения не нужна. Для кода выбирай релевантные тесты; обе компиляции
проверяют платформенную совместимость, lintDebug — Android Lint.

Фиксируй команду, exit code и результат; сохраняй полный log там, где этого требует
задача, не добавляя отчёты в репозиторий без необходимости. Различай FAIL кода,
BLOCKED окружением и SKIPPED. Не сохраняй секреты в выводах.
Определи требуемую Java по Gradle-файлам и gradle/gradle-daemon-jvm.properties:
сейчас toolchain, JVM target и критерий daemon — Java 21. При отсутствии Java
используй установленный JDK через JAVA_HOME процесса; Android Studio JBR может
служить launcher, но её версия не заменяет требуемую toolchain. Не меняй глобальное
окружение или Gradle-версии.
Не выдавай отсутствие ktlint/detekt за успешный lint и не исправляй несвязанные
toolchain-проблемы. Результат: команды, реальные totals тестов, дефекты и ограничения.

Источники: https://developer.android.com/topic/architecture/recommendations
и https://kotlinlang.org/docs/exception-handling.html
